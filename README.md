# prozorro-check

Бот, який шукає підозрілі тендери на Prozorro і скидає їх мені в Telegram. Що схвалю, те йде в X (або тільки в телеграм-канал).

Крутиться на GitHub Actions раз на 30 хв.

## Як працює

- `prozorro_monitor.py` тягне нові тендери з API Prozorro, складає в SQLite і рахує прапорці: одна пропозиція, ціна сильно вища, ніж у інших замовників, дешевших учасників відхилили і т.д.
- `prozorro_publisher.py` бере найцікавіші випадки, пише чернетку і шле в Telegram з кнопками Опублікувати / Редагувати / Відхилити.
- Схвалене виходить на наступному проході, тобто десь через 30-60 хв. Без кнопки нічого не публікується.

База лежить у кеші Actions, а рішення і позиція завантаження в `state/ledger.json` (бот сам його комітить). Якщо кеш зникне, нічого не задвоїться.

Прапорець - це привід подивитися уважніше, а не доказ порушення.

## Налаштування

Секрети: Settings → Secrets and variables → Actions.

- `TG_BOT_TOKEN` - токен від @BotFather
- `TG_ADMIN_IDS` - свій id (від @userinfobot), можна кілька через кому
- `TG_REVIEW_CHAT_ID` - куди слати чернетки, зазвичай той самий id
- `TG_CHANNEL_ID` - @канал, якщо треба публікувати в Telegram (бот має бути адміном каналу)
- `X_API_KEY`, `X_API_SECRET`, `X_ACCESS_TOKEN`, `X_ACCESS_SECRET` - не обов'язково. Без них бот надсилає посилання, яке відкриває X з готовим текстом, і я тисну Post сам.

Не забути натиснути Start у боті, інакше він не зможе писати.

В `publisher.json`:

- `"post_to_x": false` - публікувати тільки в телеграм-канал (тоді потрібен `TG_CHANNEL_ID`)
- `"channel_minutes_between_posts": 60` - у телеграм-канал по одному посту приблизно раз на годину (X-посилання приходять усі разом)
- ліміти: денного ліміту немає (`"max_posts_per_day": 0`), у канал - раз на годину, тихі години 23:00-08:00 за Києвом
- `"pattern_types"` - які закономірності надсилати; `buyer_direct` (частка прямих договорів) вимкнено, бо для енергетики це норма
- `"explore_share": 0.25` - частка пошукових чернеток
- `"digest_hour_kyiv": 18` - щонеділі з 18:00 бот шле мені статистику тижня, а в канал - підсумки тижня

Перший запуск: Actions → prozorro-bot → Run workflow, `since` = дата днів 10 тому, `limit` = 40000. Потім ще раз з порожнім `since`, поки в лозі є "досягнуто max_tenders_per_run".

Якщо репо приватне, краще поставити cron раз на годину (`"7 * * * *"`), бо безкоштовних хвилин 2000 на місяць.

Команди в Telegram: `/pause`, `/resume`, `/queue`.

Перевірити локально без публікації: `python prozorro_publisher.py --dry-run ci`

## Закономірності і пошукові випадки

Крім окремих тендерів, бот шукає підозрілі закономірності, де може й не бути переплати (`prozorro_patterns.py`):

- один постачальник забирає більшість конкурентних закупівель замовника (за 180 днів)
- кілька допорогових закупівель одного предмета, які разом перевищують поріг (можливий поділ)
- замовник, у якого майже всі конкурентні тендери з однією пропозицією

Для цього є окрема таблиця «хто в кого що виграв», яка живе ~400 днів. Військових замовників тут не чіпаю.

Приблизно кожна п'ята чернетка - пошукова (🧪): випадок, який не пройшов звичайні фільтри. Це щоб модель вчилась і на тому, що зараз відсіюється.

Ліміту на кількість чернеток немає: приходять усі, що пройшли поріг.

## Тіньова модель

`prozorro_model.py` вчиться на моїх ✅/❌ і передбачає, чи схвалю я чернетку. Бот її поки не використовує, вона просто вчиться.

- `state/decisions.jsonl` - знімок ознак кожного рішення (база тендерів чиститься, а це лишається)
- `state/model.json` - ваги моделі і точність (рахується, коли рішень 20+)
- `state/shadow.jsonl` - прогнози для нових чернеток, щоб потім звірити з реальними рішеннями

Щоб модель була корисною, треба десь 50-200 рішень, причому і схвалених, і відхилених.

## Дрібниці

- Військові та безпекові закупівлі (ЗСУ, НГУ, поліція, СБУ тощо) поки повністю вимкнені: `"include_military": false`, `"include_security": false`. Якщо колись увімкнути військові, вони анонімізуються і виходять із затримкою 14 днів.
- ФОП у постах не називаю (це приватні особи), у пості є тільки ЄДРПОУ юросіб.
- Якщо прохід впаде, в Telegram прийде повідомлення з посиланням на лог.
- GitHub запускає cron із запізненням 5-20 хв, це нормально.
- У публічному репо розклад вимикається після 60 днів без комітів, але бот комітить журнал, тож ок.
- Пороги в коді варто звірити з чинними правилами (воєнний стан).
